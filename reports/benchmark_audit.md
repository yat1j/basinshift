## 2. Task 1: Feature Leakage Audit

A comprehensive feature availability audit was conducted on every input variable generated by [`src/basinshift/features.py`](file:///d:/hackathon/basinshift/src/basinshift/features.py). The complete line-by-line inventory is saved to [`reports/feature_availability_audit.csv`](file:///d:/hackathon/basinshift/reports/feature_availability_audit.csv) (51 rows).

### Audit Findings:
1. **Strictly Backward Rolling Windows:** In pandas, `rolling(W, min_periods=1)` defaults to right-aligned windows covering timestamps $[t - W + 1, t]$. For example, `precip_sum_3d` at date $t$ computes $P_{t-2} + P_{t-1} + P_t$. No future dates ($t+1, t+2, \dots$) enter any rolling calculation.
2. **Exponentially Decayed Antecedent Precipitation Index (API):** Computed recursively using `ewm(alpha=(1 - alpha), adjust=False).mean()`. The recurrence relation $API_t = P_t + \alpha API_{t-1}$ is strictly causal and incorporates solely historical rainfall.
3. **No Operational Future-Weather Feed:** The current dataset provides historical ERA5-Land reanalysis up to date $t$. No future meteorological forecasts ($t+1 \dots t+7$) are provided or used as model inputs.
4. **Catchment Boundary Isolation:** All rolling windows, lags, and shifts are grouped by `catchment_id` (`df.groupby('catchment_id')`). At catchment boundaries, lags and backward differences evaluate to `NaN` and never incorporate observations from adjacent catchments.

## 5. Task 4: High-Flow Threshold ($Q_{95}$) Audit

### Audit Details:
1. **$Q_{95}$ is NOT a Model Input:** $Q_{95}$ is completely absent from all model feature dictionaries. Tree models predict continuous streamflow without threshold conditioning.
2. **Test A Derivation (Clean):** In Development catchments, $Q_{95}$ is derived strictly from historical training observations ($t \le 2012\text{-}12\text{-}31$).
3. **Test B Ground-Truth Mask vs. Operational Alerting:**
   - In [`src/basinshift/train_evaluate.py`](file:///d:/hackathon/basinshift/src/basinshift/train_evaluate.py#L65-L67), $Q_{95}$ for the 30 holdout catchments was computed using their 10-year records (2005–2014).
   - This functioned solely as an *evaluation ground-truth label mask* (identifying which validation events were objectively in the top 5% of flow for computing `high_flow_rmse`).
   - However, in truly ungauged catchments (PUB), a gauge does not exist. An ungauged model deployed in the wild cannot look up historical streamflow to determine $Q_{95}$.
4. **Resolution for Stage C:**
   - In Stage C event classification, threshold heads will use **regional training-derived specific discharge thresholds** (e.g. median $Q_{95}$ across climatically similar training basins) so that flood alerts can be triggered in truly ungauged basins without historical gauge data.

## 9. Task 8: Corrected Hydrological Interpretations

In accordance with scientific rigor:
1. **7-Day Predictability Ceiling:** Removed over-optimistic claims regarding 7-day lead skill. The benchmark report now explicitly states that without an operational future weather forecast feed, 7-day streamflow forecasting is physically limited (achieving Median NSE of only ~0.04 in gauged mode and -0.013 in ungauged mode, barely improving upon climatology).
2. **Gauged Transfer vs. Ungauged PUB:** The report clearly distinguishes between:
   - **Gauged Transfer:** An unseen basin where historical streamflow up to origin $t$ is recorded.
   - **Ungauged Transfer (PUB):** A truly ungauged basin with zero streamflow data.
3. **Pilot Scope Caveat:** Clarified that the current 150-catchment dataset represents a two-continent pilot (CAMELS-US and CAMELS-AUS) rather than global coverage.
